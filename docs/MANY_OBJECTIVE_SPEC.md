# apels-iqcqp many-objective specification

## Scope and compatibility

The current integer quadratic LP model has a finite objective count `m >= 2`. The LP parser, exact original-model validator, full nondominated archive, task protocol and C++ worker use the actual `m`. Source bytes, sparse terms, variable/constraint counts, address space, tree RSS, time and native integer parsing remain finite resource limits. A failed heuristic search is `UNKNOWN`, not an infeasibility certificate. The output is a validated nondominated *sample*, not a complete Pareto front.

`fixed` retains the 0.3/0.5/0.2 measured-service default. For 2–4 objectives its task construction and random sequence remain on the legacy path. `adaptive` is the legacy exact 2D HV scheduler and requires an `hv-v1` specification. `adaptive_r2` uses the same task construction, window and selection rule with the `r2-asf-v1` reward. New Fixed and Adaptive-R2 runs at the same dimension therefore share task construction and native search. Fixed parses and validates an optional R2 spec without paying online reward cost.

## Search tasks

Direction tasks rotate single-objective directions and interleave random positive directions. Feasibility is used only while the full archive is empty and is never a learning arm. Direction and PLS become eligible with one distinct objective vector; epsilon needs two, drawn from the full archive even if `work_capacity=1`. PLS is bounded integer-neighborhood sampling.

At `m=2`, epsilon keeps the legacy gap rule. At `m=3,4`, it keeps the legacy observed-cell sparse-grid rule. At `m>=5`, it uses the same sparse observed cells, with an epsilon-task counter rotating the primary objective. It chooses a representative of a least populated observed cell; all other objectives get thresholds at that point. One secondary coordinate `q` is tightened by `eta*scale[q]`, while the others are loosened by that amount. `q` rotates across nonprimary objectives; `eta` cycles through 1/100, 3/100 and 1/10. The primary objective gets no threshold and receives the principal search weight. The seed minimizes normalized positive threshold violation among work points. Only populated cells are stored; no `20^m` grid is allocated. Temporary epsilon violation is distinct from original-model infeasibility: every returned assignment is validated against the original model and can enter the full archive even if it violates the temporary threshold.

`A_work` is a bounded search proxy. For `m>4`, when distinct coordinate extrema exceed capacity, successive calls rotate through the extrema; consequently a single work set need not contain every extreme. The full archive is never truncated to satisfy work capacity. Under RSS pressure, the run stops and retains only assignments validated before the deadline.

## Frozen signed ASF/R2

All original maximization objectives are negated to internal minimization values `f_j`. Freeze finite origin `o_j`, strictly positive scale `s_j`, and a finite nonempty list `W` of nonnegative rational vectors summing to one **before** a run. The run configuration contains every actual coordinate and weight; its canonical content hash enters the result and queue identity. Our normalization and scalarization are

    y_j(x) = (f_j(x) - o_j) / s_j
    g_w(y) = max_j w_j y_j
    I_R2(A) = (1/|W|) sum_{w in W} min_{x in A} g_w(y(x)), A nonempty.

Smaller `I_R2` is better. A completed nonfeasibility batch earns `I_R2(A_before)-I_R2(A_after)`. All values are exact Python `Fraction`s; no floating clamp changes the gain. The default development generator freezes `m` singleton weights and 32 deterministic positive rational combinations. The actual list, not merely a seed, is saved. New generation uses `r2-asf-box-v2`: exact integer-box independent-term intervals, internal origin L_j and scale U_j-L_j (or a documented positive unit1 for a constant coordinate). It binds per-coordinate L/U/units/proof/algorithm, input/model and normalization/weight content hashes. It can be loose; it does not estimate actual Pareto variation. Explicit finite coordinates require per-coordinate proof metadata; unproved origins retain their documented signed blind spots. Legacy `r2-asf-v1` remains unchanged and has no automatic lower-bound guarantee. The HV worse reference is never reused as an R2 ideal point.

Nonnegative weights make every `g_w` coordinatewise nondecreasing, including with negative normalized coordinates. Thus a dominated point cannot improve any weight's minimum, and removing a dominated point after admitting its dominator cannot worsen it. Duplicate and dominated candidates earn zero. The incremental cache stores per-weight minima over every point ever admitted; because the full archive changes only by nondominated admission and dominated removal, these minima equal recomputation over the current full archive. A value call builds local copies and commits them only after all points, weights and deadline checks succeed. A timeout leaves the prior cache intact. Feasibility initializes the archive without arm feedback; the first learning task synchronizes the cache. Incomplete global-deadline feedback is censored.

With this exact signed formula, a singleton weight has zero-weight coordinates contributing zero to the maximum. If its active normalized objective is negative, its ASF value is therefore floored at zero. The vectors are still frozen coordinate-direction preferences; an arbitrary origin is not silently treated as an ideal point, and users should choose origin and scale with this behavior in mind.

Naive recomputation costs `O(|W| m |A|)` scalar operations; incremental updates cost `O(|W| m)` per new admitted point, plus exact rational arithmetic and full-archive dominance checks. This finite-weight R2 does not equal HV and may give zero gain for a real Pareto improvement. It does not guarantee complete preference or front coverage. The signed ASF definition follows Wagner, Trautmann and Brockhoff, [*Preference Articulation by Means of the R2 Indicator*](https://www.cmap.polytechnique.fr/~dimo.brockhoff/publicationListFiles/wtb2013a.pdf), Eq. (1). No absolute value is inserted: doing so for an origin that is not a proved ideal point would lose the required monotonicity.

## Learning, time and metrics

Both Adaptive modes retain the latest 30 valid arm completions, `sum(gain)/sum(service)`, independent selection RNG, forced exploration at zero completed-plus-pending count, and the pending-adjusted UCB-style score in [ADAPTIVE_SPEC.md](ADAPTIVE_SPEC.md). There is no standard UCB1 regret claim or FRRMAB equivalence. Service includes worker active wall and coordinator batch validation/admission/reward wall; scheduling, event writes and checkpointing consume the global deadline and are recorded separately. Valid zero gains enter the window. Infrastructure errors stop the run.

Exact offline HV remains available for 2–4 objectives when explicitly requested and correctly referenced. High-dimensional success does not compute HV. Without an HV request, output says `HV=NOT_COMPUTED`; it never substitutes zero. Adaptive-R2 results record the reward type, spec hash, direction and exact online value if a complete in-budget cache exists, otherwise `NOT_COMPUTED`. Saved assignments contain all original and internal objective values and variable mapping. Independent post-run enumeration and R2 evaluation belong to the development report, not the timed online reward.

The method combines known multi-directional local search, adaptive operator selection and R2 indicator ideas; dimension generality alone is not a claim of new theory. Relevant prior work includes [MDLS](https://prolog.univie.ac.at/research/MDLS/), [FRRMAB](https://colalab.ai/publications/LiFKZ14.pdf), and [Adaptive MOLS](https://discovery.ucl.ac.uk/id/eprint/10068495/1/lion_2018_preprint.pdf). APELS has no verified English expansion in this project.

## Repair v7: first feasibility and normalization

See FIRST_FEASIBLE_REPAIR_SPEC.md. All modes default to persistent_unit_v1 with 10-second empty-archive slices. Normal slices retain their original budget-dependent defaults unless explicitly configured (formal comparison1 second). Legacy replay requires bootstrap_strategy=legacy_v1. New bootstrap consumes no task construction RNG, so end-to-end trajectories differ; legacy Fixed2/3/4 task/RNG construction and legacy-HV selection remain covered by explicit replay tests. A very short global budget can expire within the first10-second logical slice before COLLECT/validation; this yields UNKNOWN. Functional micro-tests explicitly use shorter feasibility slices and provide no300-second performance evidence.

An independently rotating feasibility unit cursor is used for second_witness under the new strategy. Native TASK/WARM, total reset and deadline recovery counts, first floating feasible timestamp/assignment and zero-step slices are logged. Counters are latest completed-response observations; a cancelled final slice can be censored. First floating observation is not exact admission. Feasibility admissions synchronize an R2 cache without reward, including after normal tasks are already pending. Each normal result snapshots the current complete archive immediately before its own validation batch, preventing bootstrap gains from being attributed to it.

For a declared reliable lower bound, every exactly feasible candidate is checked, including dominated and duplicate points. A violation saves normalization_violation_audit and stops with ERROR. Box provenance is rederived and checked before search. Explicit declared_reliable means an external assertion, not a solver proof; unproved means no guarantee. Origin/scale/W remain frozen. For unit e_k, max(y_k,0)=y_k when the lower-bound normalization makes y nonnegative. Strictly positive weights do not have the same zero-coordinate floor. The signed ASF and finite-weight mean-min formula are unchanged; formula continuity does not imply configuration identity continuity.

The source, actual native and coordinator hashes, actual m, bootstrap strategy/slice, R2 schema and full provenance/content all enter v9 identity. Old results are never reused. Finite-weight R2 is not HV, can miss a Pareto improvement and does not certify the full front. The UCB-style schedule has no standard UCB1 regret guarantee. The definition follows Wagner, Trautmann and Brockhoff (2013), Eq.(1), https://www.cmap.polytechnique.fr/~dimo.brockhoff/publicationListFiles/wtb2013a.pdf; our normalization and conservative bounds are engineering choices.
